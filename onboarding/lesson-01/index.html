1

用 Claude 網頁版做網頁

Chat 模式 · 約 3 分鐘

開一個新對話，把測試題貼進去發送。Claude 會自己找資料、分析、做出一個網頁（artifact），大概要跑 3 分鐘，先讓它跑。

  • 注意模式：要用 Chat 模式（在 Claude 雲端主機工作，能直接發佈）。如果你左邊看到 Cowork 模式，那是在你自己電腦工作、不會自動發佈——做網頁要發佈請切回 Chat。
  • 隨機性是正常的：有時它只把內容印出來、沒做成網頁。沒關係，再補一句就好：
幫我做成網頁
心法哪怕是全世界最厲害的產品，也有隨機出錯的時候。出錯了不用慌，再發送一次就好。
2

用 Claude 網頁版直接發佈

最快 · 一個連結分享全世界

網頁做好後，在 artifact 畫面：

  1. 右上角的下拉選項找到 Publish artifact
  2. 幫它命名 → 按 Publish
  3. 變成 Open the link → Copy link
  4. 把連結貼出去，任何人都能看到你的成果
想收回同一個地方按 Unpublish 就不再公開。你發佈過的東西可以在 Claude 設定裡找到清單。
3

用 Netlify Drop 發佈靜態網頁

拖資料夾就上線 · 無限個

當你手上是一個下載好的 HTML 檔（或一整包資料夾），想自己發佈，就用 Netlify。忘記怎麼用？直接問 Claude：

我想要免費發佈靜態網頁，超級簡單、免費，用什麼工具？請教我步驟
  • 用 GitHub 帳號登入（不用另記帳密、好管理）
  • 填資料時：公司名可跳過或填 N/A；身份選 personal / other / student——最基本的個人身份通常全部免費
  • 把網頁拖進去就上傳，按那行綠色連結就發佈完成
兩個小坑① 發佈失敗很常見，重做一次常常就好。② 直接拖檔到 Netlify Drop 雖快，但容易忘記丟到哪、之後找不到；想長期管理，改從官網登入用帳號發佈。（對照：Cloudflare Pages 也免費，但拖檔最多只能放一個網頁；Netlify 可以無限個。）
4

用 Claude CLI 連動 GitHub 建新 repo

本地端 · 火車模式

本地端（終端機裡的 Claude）才是真正的主力。先確認裝好：裝 Node.js → 終端機輸入 claude 按 Enter，看到歡迎畫面（顯示 4.8 模型、權限、工作目錄）就代表成功。歡迎動畫每次長得不一樣，是正常的。

起頭指令二選一
claude
claude --dangerously-skip-permissions
  • claude ＝ 安全模式：每個動作都先問你「可以這樣做嗎？」
  • --dangerously-skip-permissions ＝ 暴力模式：它覺得可以就直接做、不問你
什麼時候別用暴力模式電腦裡有很多珍貴資料、又沒有異地備份，刪掉會哭——就乖乖用安全模式。備份做好了再考慮放手。
官方真實含義 · 進階補充 「安全／暴力模式」是上課為了好記的比喻。它真正做的事是：Claude Code 在動你的檔案、執行終端機指令前，每次都會先跳出權限確認，這道人工關卡同時擋住「不小心的破壞」與「提示注入（prompt injection）攻擊」。--dangerously-skip-permissions 的作用是跳過所有這些確認（官方原文：「Skip permission prompts」，等同 --permission-mode bypassPermissions）。所以它不是「變強、變暴力」，而是「拿掉那道人工把關」。

官方之所以在名字裡放 dangerously，是因為讓 AI 無人看管地執行任意指令，可能造成資料遺失、系統損壞，甚至被提示注入偷走資料。因此官方建議：只在沒有對外網路的隔離容器裡使用；若只是想少一點打擾、又不想拿掉把關，可改用更安全的 Auto 模式（有分類器在每個動作執行前先審查）。
原始文件出處 ↗ Claude Code CLI 參考 — 旗標定義 Permission modes — bypassPermissions 跳過／不跳過什麼 Anthropic 工程部落格 — 更安全的 Auto 模式

建立 repo 三句話（依序貼給 Claude，「」裡換成你自己的）：

我等等要在這裡工作 「貼上你的專案資料夾位置」
我現在在上示範教學課程，我要用這個資料夾，也和我的 GitHub 帳號「你的帳號」連動使用，請幫我建立一個會議記錄的新 repo
小提醒找不到自己的 GitHub 帳號？打開瀏覽器你的 GitHub 頁面，網址最短的那一段就是。建立新資產時選私有（Private）——公開＝全世界看得到，沒必要就一律私有。
5

把別人分享的 repo 拉（pull）下來

共編協作的關鍵

未來 PM 發任務，常常就是共享一個 repo 給你。對方在 repo 的 Settings → Collaborators 加你的帳號邀你（需先用 GitHub App 做手機數位認證，這步省不了）。你這邊要做兩件事：

  1. 打開合作專用信箱，接受 repo 邀請（沒接受會出現 404 / 找不到擁有者）
  2. 把 repo 名字貼給本地端 Claude，請它拉下來：
剛剛同事分享了這個 repo 給我 cyc-meetings，請你幫我拉下來

不知道它拉到哪了？直接問：

請幫我看看拉下來的 repo 你放在哪裡，把資料夾的位置印給我
在哪裡找得到別人分享給你的 repo，不在「My repositories」，而在 Contributions（因為擁有者不是你，你是協助者）。被邀請的是編輯權限，所以你可以直接在裡面幫忙做東西。

#做什麼
—前置 · 把環境與帳號準備好
·確認 Claude 訂閱成功、GitHub 已註冊、雙重驗證（Microsoft Authenticator）已開
—連動 · 建立你自己的 repo
1建立本地端的專用資料夾（命名習慣：GitHub--帳號別，例 GitHub--cameocyc）
2複製資料夾位置，回終端機說：我等等要在這裡工作「貼上資料夾位置」
3…我要用這個資料夾，也和我的 GitHub 帳號「你的帳號」連動使用，請幫我建立一個會議記錄的新 repo（選 私有）
4檢查本地端建立是否成功（打開資料夾看有沒有東西、README）
5檢查線上建立是否成功（去 github.com/你的帳號/repo名）
6檢查所有發佈過的 repo（左上角漢堡選單 → All repositories）
—協作 · 分享與拉取
7共享 repo：Settings → Collaborators → 數位認證 → 收集大家帳號 → 邀請（編輯權限）
8請 Claude 拉下別人分享的 repo：剛剛同事分享了這個 repo 給我 cyc-meetings，請你幫我拉下來
9到自己信箱接受 repo 邀請（沒接受會 404）
10請幫我看看拉下來的 repo 你放在哪裡，把資料夾的位置印給我
11線上檢查是否也看得到新 repo（協助者的 repo 在 Contributions）
04關鍵觀念對照

CLAUDE WEB · 跑車

  • 快、漂亮、好上手
  • 環境固定，能力有上限

  • 什麼都得自己 DIY
  • 最強、什麼都能做
  • 在你自己電腦上工作
  • 真正承接任務的主力

Chat 模式

雲端主機環境
  • 在 Claude 的網路主機上工作
  • 做完可以立刻 Publish 發佈

Cowork 模式

你的電腦環境
  • 下載 App 後才會出現
  • 成果只留在你電腦、不自動發佈
05卡關速查

這是整堂課最該帶走的一招——遇到任何卡關，截圖丟給 Claude，貼上這句：

我卡在這裡，請教我，給我指令就好，不要告訴我太多我聽不懂的東西。下一步是什麼？
狀況處理方式
複製的東西在終端機貼不上去（Windows）不要按 Ctrl+V，改用滑鼠右鍵貼上
終端機字太小（Mac）Command + + 放大，像瀏覽器一樣
要把畫面問題問 ClaudeMac 截圖 Command+Shift+4 → 拖進終端機，或貼到網頁版新對話（有圖有文更好溝通）
下載雙重驗證 App 被要求付費那是假的／釣魚——雙重驗證一定免費。到 App Store 搜 AUTH，認明藍色盾牌中間一把鎖（Microsoft Authenticator）
CLI 說要先裝 GH那是 GitHub CLI（終端機跟 GitHub 溝通的套件），請它幫你裝一次，之後就不會再遇到
終端機呼叫不出瀏覽器授權確認瀏覽器登入的是同一個帳號；Windows 可能要開某個隱私權設定——卡住就截圖問群組
